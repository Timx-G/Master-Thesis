# 开题与中期答辩材料设计规格

- **日期：** 2026-07-12
- **状态：** 用户已批准方案 A，并要求新实验数据使用占位符
- **适用课题：** 面向全频复用多无人机 NOMA-MEC 网络的干扰感知用户配对与截止时间资源分配研究
- **学生：** 关铭锡
- **导师：** 曲桦

## 1. 交付目标

在新版本完整实验尚未结束的情况下，先交付可用于开题和中期答辩准备的四份正式材料：

1. 开题报告 DOCX；
2. 开题答辩 PPTX；
3. 中期报告 DOCX；
4. 中期答辩 PPTX。

材料必须围绕专业型硕士论文组织，突出工程问题、可实现算法、可复现实验和应用价值。所有性能结论只允许来自新 canonical 实验；当前未完成的数据统一使用可机器替换的占位符，禁止引用旧 `results/`、历史 DRL 结果或已被审计否定的数字作为新论文证据。

## 2. 内容定位

### 2.1 开题材料

开题报告和开题 PPT 回答五个问题：

1. 多 UAV 全频复用 NOMA-MEC 为什么存在真实工程矛盾；
2. 现有工作在哪些环节没有同时处理真实服务归属、跨 UAV 干扰、SIC 和 deadline；
3. 两个创新点分别解决什么问题，为什么相互独立又能联合；
4. 数学模型、算法流程和实验验证如何闭环；
5. 研究计划是否能在专业硕士培养周期内落地。

开题材料不宣称算法已经获得性能优势。实验页展示完整实验矩阵、评价指标、统计方法和数据占位图。

### 2.2 中期材料

中期报告和中期 PPT 回答六个问题：

1. 前期研究为什么从轨迹优化/DRL 转向固定悬停下的调度与资源分配；
2. 旧实现发现了哪些会改变结论的系统性问题；
3. 已经完成哪些可信重构、数学推导和自动化测试；
4. 两个创新点当前分别推进到什么阶段；
5. 新实验尚未完成时，如何诚实描述阶段成果；
6. 剩余工作、风险和毕业答辩时间表是否可控。

中期材料允许使用当前可核验的工程事实，例如已完成任务数、测试数、公式交叉验证和提交记录；不得把这些事实包装成尚未得到的算法性能结论。

## 3. 双创新表述

### 创新点一：干扰外部性感知的跨 UAV 联合关联与配对

使用单一显式 `Schedule` 表达任务、用户、服务 UAV、子载波和 NOMA 角色。以实际服务信道重算强弱次序、SIC 和跨 UAV 同频干扰，并通过 Replace、Position、CrossUAV 三类确定性邻域联合优化用户关联与配对。

### 创新点二：面向截止时间满足数的卸载与 MEC 算力分配

从并行部分卸载时延模型解析推导最小卸载比例和最小 MEC CPU 需求，将网络目标转化为单位收益、可加成本的最大基数选择问题；在硬 CPU 预算下使用稳定最小成本前缀获得可证明的最大按时完成任务数。

材料必须把两个创新点画成前后连接但评价对象不同的模块：创新点一决定调度与无线速率，创新点二决定在该调度下实际完成哪些任务。

## 4. 数据占位符规范

所有待新实验填充的内容采用 `{{PLACEHOLDER_KEY}}` 形式。占位符至少覆盖：

- 主实验各算法按时完成率、置信区间和运行时间；
- 严格 2x2 消融；
- SIC 门限敏感性；
- UAV 数量与用户数量扩展性；
- CSI 误差鲁棒性；
- 小规模完整枚举最优差距；
- 两个创新模块的独立贡献；
- canonical manifest、代码提交和实验日期。

同时生成 `data_placeholders.json`，每项记录：键、中文含义、单位、预期 canonical 来源、应填入的报告/幻灯片位置和当前状态。图表占位区域显示“待新版本 canonical 实验填充”，不得使用虚构柱高或折线点。

## 5. 文档结构

### 5.1 开题报告

目标长度约 10-15 页，包含：封面、摘要与关键词、背景意义、国内外现状、问题与审计动机、系统模型、研究目标、两项创新、技术路线、实验与统计设计、进度计划、风险控制、预期成果、参考文献。

### 5.2 中期报告

目标长度约 10-15 页，包含：封面、课题概况、前期路线与科学纠偏、可信性审计、当前架构、阶段性理论成果、已完成工程工作、阶段验证、待填实验结果、剩余计划、风险与资源、预期答辩材料、参考文献。

报告默认采用通用中文高校学术格式。学校、学院、专业、学号和提交日期使用醒目的可编辑占位符。

## 6. PPT 结构与视觉设计

### 6.1 开题答辩 PPT

约 14 页：封面、问题场景、研究动机、现状缺口、研究问题、系统模型、总体路线、创新点一、创新点二、联合工作流、实验设计、数据占位页、计划与风险、总结。

### 6.2 中期答辩 PPT

约 16 页：封面、课题目标、路线演化、旧方案为何调整、可信性审计、重构原则、当前完成度、创新点一进展、创新点二进展、数学推导、测试与复现、实验占位页一、实验占位页二、剩余计划、风险闭环、总结。

视觉采用 16:9、白色主体页、深青绿主色、暗红风险/约束强调、深灰正文。标题页和总结页可使用深色背景。每页必须包含图形、流程、矩阵、时间线、原生图表占位框或状态可视化，避免纯文本页。字体使用 Calibri/Arial/Cambria 等可可靠渲染字体；中文由系统兼容字体替代时预留足够空间。

## 7. 可编辑性与复现

交付目录同时保留：

- DOCX 和 PPTX 成品；
- Markdown 报告源文件；
- PptxGenJS 源文件；
- 数据占位符 JSON；
- PPT PDF 预览和逐页渲染图；
- 内容与视觉 QA 记录。

PPT 中的流程、表格、时间线和常规图表必须保持 PowerPoint 原生可编辑。生成后执行文本提取、占位符扫描、LibreOffice PDF 转换和逐页视觉检查；至少完成一次修复与复验。

## 8. 真实性边界

1. 当前 `121 passed` 仅表示截至 `fd0cb7c` 的软件测试状态，可用于中期工程进展，不等同于算法性能。
2. 已完成的物理层修复、解析资源公式和最大基数分配器可作为阶段性成果。
3. 创新点一尚未完成实现时，必须使用“设计完成/待实现/进行中”等准确状态。
4. 旧结果只用于解释研究路线为何调整，不作为新方案优越性的证据。
5. 所有最终性能结论必须在新 canonical 实验完成、统计检验通过并生成 manifest 后替换占位符。
