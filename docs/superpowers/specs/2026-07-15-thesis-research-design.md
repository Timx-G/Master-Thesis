## 1. 设计目标与边界

本方案完整规定论文的问题定义、算法设计、理论分析、实验方法和证据要求。方案 B 的范围为：

## 3. 核心研究问题

### RQ1：全频复用导致的外部性是否被正确建模和识别？

当用户从一个 UAV/子载波位置移动到另一个位置时，改变的不只是参与交换的用户。该动作会改变所有 UAV 在相同子载波上的接收干扰、NOMA 解码顺序、SIC 可行性、实际速率、最小 MEC CPU 需求和完成状态。需要证明 IEA-CAP 的全网评价确实捕获这些第三方变化，而不是仅更换一个局部效用名称。

### RQ2：IEA-CAP 是否具有明确算法性质和可测性能收益？

需要证明严格接受动作使全网字典序目标单调改善、算法有限终止，且在穷尽给定邻域后达到局部最优。同时需要用外部性压力场景、精确小实例和强同口径基线说明它何时有效、效果多大、代价多高。

### RQ3：DD-MCAA 为什么不是普通启发式排序？

需要从硬截止约束反推出最小卸载比例和最小 MEC CPU，并证明在固定无线调度、单位任务价值、独立最小 CPU 消耗和逐 UAV CPU 预算条件下，按最小 CPU 需求排序取最长可行前缀能获得最大完成任务数。

### RQ4：两个方法的联合是否产生可辨识贡献？

需要通过“无线调度方法 × 资源分配方法”的 2×2 配对实验分离 IEA-CAP 主效应、DD-MCAA 主效应和交互效应，不能只比较最终联合方法与两个明显较弱的控制组。

### RQ5：结论是否跨负载、规模、信道误差和任务模式成立？

需要覆盖非饱和、临界和过载场景，保持等人均负载扩展 UAV 数量，并使用周期、周期抖动、随机突发以及真实 GPS 移动轨迹补充验证适用边界。

## 4. 最终系统模型

### 4.1 网络与调度对象

- 系统包含 `K` 架位置固定的悬停 UAV，每架 UAV 搭载一台 MEC 服务器；
- `N` 个地面用户在二维区域内移动，UAV 高度固定；
- 所有 UAV 复用同一组 `S` 个子载波，即跨 UAV 全频复用；
- 每个 UAV/子载波资源块最多接入 2 个上行 NOMA 用户；
- 每个到达任务最多由一个实际服务 UAV、一个子载波和一个 NOMA 解码角色服务；
- 用户发射功率在主问题中固定，UAV 轨迹、飞行能耗和跨 UAV 任务迁移不属于本文决策变量。

逐 UAV CPU 预算表示为向量 `F=(F_1,...,F_K)`；主场景各元素均为 `4 GHz`，异质性实验只改变该向量。DD-MCAA 的准入定理逐 UAV 独立应用，不要求各 UAV 预算相同。

显式调度对象记为：

`x_i = (served, uav_id, subcarrier_id, noma_role)`。

其中 `noma_role` 是完成用户集合分配后，按目标 UAV 接收功率唯一规范化得到的派生字段，不是邻域动作可自由指定的变量。这一对象是唯一任务语义、真实接收端、跨 UAV 干扰重算和结果审计的共同数据源。

### 4.2 信道、全频复用与 SIC

主信道采用 Al-Hourani Urban 的 LoS/NLoS 概率加权期望大尺度信道增益，不包含瞬时小尺度衰落。3GPP TR 36.777 的 UMa-AV 场景作为鲁棒性复核，配置必须冻结适用高度、LoS 概率、LoS/NLoS 路径损耗、阴影衰落条款及对应表号，并依据链路互易性映射为地面用户到空中接收机链路。正文统一使用“真实大尺度信道增益”和“估计大尺度信道增益”，不称为完整瞬时信道状态信息。每个候选调度均按实际服务 UAV 计算：

1. 用户到服务 UAV 的期望接收功率；
2. 同一 UAV/子载波内另一个 NOMA 用户的组内干扰；
3. 其他 UAV 在相同子载波上所有发射用户造成的跨接收端同频干扰；
4. 基于接收功率的 NOMA 解码顺序；
5. 带残余 SIC 的解码 SINR；
6. 每一层的 SIC 门限和最终上行速率。

跨 UAV 干扰不由 SIC 直接消除。SIC只在同一接收 UAV 的 NOMA 组内执行；跨 UAV 干扰通过关联、子载波位置和配对的联合重排进行规避，并在每个候选方案上进行全网精确反馈。

### 4.3 周期性时限任务

每个用户生成周期性作业 `J_{i,r}`。任务属性包括释放时刻 `a_{i,r}`、输入数据量 `L_i`、计算密度 `c_i`、绝对截止时刻 `d_{i,r}`、本地 CPU `f_i^loc` 和结果数据比例 `rho_i`。释放时刻按 `a_{i,r}=slot_index*Delta_t` 换算为秒，剩余时限为 `tau_i=d_{i,r}-a_{i,r}`，避免把时隙编号与秒直接相加。

主轨迹为每个用户在种子初始化时一次性冻结 `(period_i, phase_i, L_i, c_i, tau_i)`，后续作业重复使用同一任务流参数。周期按 `Pr(period_i=2)=2/3`、`Pr(period_i=3)=1/3` 抽取，初相位在一个周期内均匀分布，使长期平均释放概率约为 `0.444`。约束 `0<tau_i<=min(period_i*Delta_t, Delta_t)`，保证相邻作业不重叠且主模型保持时隙内完成。任务身份使用 `(user_id, job_index)`，序列化为确定性整数时也由 job index 生成，不再依赖 `slot*N+user` 的单作业假设。扩展轨迹包括：

- 周期抖动：每个作业只允许 `0` 或 `1` 个时隙的单向延迟抖动，并在生成时保证同一用户的释放时刻严格递增；数据量和计算量加入冻结范围内的有界扰动，长期平均作业数不变；
- 随机突发：保留当前 Markov burst/cool 过程，仅作为鲁棒性场景；
- 真实移动补充：使用 Microsoft GeoLife 中步行/骑行片段提供用户位置序列，任务释放仍按冻结的周期过程生成。

主模型要求每个作业在释放时隙内完成，不存在跨时隙等待队列。若未来引入跨时隙截止时间，必须另行实现队列、等待时延、重传和过期清理，不能混入本规格的正式数字。能够纯本地按时完成的任务直接计为本地完成，不进入无线位置搜索；只有需要卸载的任务进入 IEA-CAP 调度空间。

### 4.4 完成判定

令卸载比例为 `alpha_i`。本地和边缘分支并行执行：

`T_i^loc = (1 - alpha_i) L_i c_i / f_i^loc`

`T_i^edge = alpha_i (1 + rho_i) L_i / R_i + alpha_i L_i c_i / f_i^mec`

其中 `R_i` 是当前上行调度得到的有效无线速率，`rho_i L_i` 的结果返回流量按现有仿真器口径折算到同一有效传输速率。本文不额外虚构一个独立下行资源分配变量。任务按时完成当且仅当：

`max(T_i^loc, T_i^edge) <= tau_i`

所有算法最终都调用同一个统一时延函数复核，不允许算法内部判定与实验统计采用不同口径。

## 5. 创新点一：IEA-CAP 的最终设计

### 5.1 创新定义

IEA-CAP 是**干扰外部性感知的跨 UAV 关联与 NOMA 配对方法**。创新不在于使用局部搜索本身，而在于：

1. 将服务 UAV、子载波和 NOMA 角色统一为可审计调度对象；
2. 用 Replace、Position 和 CrossUAV 的联合邻域改变用户是否接入、资源位置和实际服务归属；
3. 对每个动作重算所有同频接收端，并把参与者收益与第三方外部性分解为可复核证书；
4. 在 DD-MCAA 完成资源响应后，以全网字典序目标接受动作；
5. 采用多起点最佳改进和精确增量评价，降低首次改进的路径依赖并控制运行时间。

### 5.2 三类邻域

令资源块为 `(u,s)`，块内容量索引为 `q in {0,1}`；容量索引只用于枚举位置，不等同于 NOMA 解码角色。空位置使用哨兵 `empty` 表示，并作为合法邻域参与者：

- `Replace(i,j,p)`：未调度任务 `j` 一对一替换位置 `p` 的任务 `i`；`Insert(j,p)` 和 `Drop(i,p)` 分别是 `i=empty` 与 `j=empty` 的特例；
- `Position(i,j,p,q)`：同一 UAV 的两个已占用位置交换；`IntraRelocate(i,p,q)` 只在目标位置为空时迁移；
- `CrossUAV`：由 `CrossSwap(i,j,p,q)` 和 `CrossRelocate(i,p,q)` 组成，前者交换不同 UAV 的两个已占用位置，后者只在目标位置为空时改变任务的服务 UAV。

每个动作完成后重新按接收功率规范化块内 NOMA 角色。正式邻域是上述全部合法动作的并集，不使用“较差位置”等不可执行描述。

空位置动作使搜索可以改变已调度任务数。对于占用无线位置但未获 MEC 准入的任务，删除动作不降低完成数，并通常降低资源成本或同频干扰，因此完整邻域不会把“无效占位”永久锁在终止调度中。

候选首先通过唯一任务、块容量、有限正信道增益，以及可证明必要的 SIC 上界条件过滤；剩余候选由统一评价器执行完整 SIC 检查。任何会改变论文结论的启发式 Top-L 截断均不得用于正式主算法；只能使用可证明不可能改进的安全剪枝。

### 5.3 全网目标

定义全网字典序目标：

`Phi(x) = (C(x), -F_min(x), -I_cross(x))`

其中：

- `C(x)` 为唯一到达任务中的按时完成数；
- `F_min(x)` 为全部已准入卸载任务的最低 MEC CPU 需求之和，纯本地任务成本为 0；
- `I_cross(x)` 为任务链路级跨 UAV 干扰和：每个已调度任务记录其服务接收端上的跨 UAV 同频干扰，同一 NOMA 块的两个任务分别计入。它是统一评价指标，不解释为物理空间中的总辐射能量。

优先级严格为：先增加完成任务数，再降低完成这些任务所需的最低 MEC CPU，最后减少跨 UAV 干扰。目标分量在比较前采用冻结的数值量化精度，CPU 为 `1 Hz`、干扰为 `1e-18 W`，并按稳定任务 ID 顺序确定性求和，以保证串并行和不同硬件上的一致判定。不得把“干扰必然单调下降”写成算法性质。

后续关于单调改进、有限终止和局部最优的命题，均以该量化后的规范化目标为准。

### 5.4 外部性证书

对动作 `m: x -> x'`，记录：

- 参与任务集合 `P_m`；
- 未参与但其速率、SIC、CPU 需求或完成状态发生变化的第三方集合 `Q_m`；
- 参与者和第三方各自的完成状态、最低 CPU、速率、SINR 与 SIC 变化；
- 按 `(receiver_uav, subcarrier)` 记录的全网 `Delta I_cross`，不对块级干扰做人为的参与者/第三方分摊；
- bilateral 判定、global 判定和最终接受判定；
- 动作前后相关资源块、服务 UAV、SINR、SIC 和 CPU 需求。

“双边有利但全网拒绝”必须能够由一条事件记录完整复现，不能只报告一个聚合计数。

### 5.5 搜索流程

1. 使用 `per-UAV ILP`、`IA-Greedy` 和 `fair-load greedy` 生成三个确定性初始解；
2. 对每个初始解调用统一全网评价器和 DD-MCAA；
3. 穷尽三类邻域中的所有合法候选；
4. 使用增量评价器重算受影响的同频接收端，以及所有包含速率/需求受影响任务的 MEC 服务器；
5. 对增量评价得到的最佳候选执行一次完整评价复核；
6. 只接受 `Phi(x') >lex Phi(x)` 的严格改善动作；
7. 按 `(Phi, initializer_id, move_type, task_id, target_position)` 确定性打破平局；
8. 当联合邻域中不存在严格改善动作时终止；
9. 从三个终止解中选择全网目标最优者作为输出。

单起点、首次改进版本保留为消融，不再作为最终 IEA-CAP。

### 5.6 增量精确评价

一次位置或跨 UAV 动作只会直接改变源/目标资源块，以及所有 UAV 在相应子载波上的接收干扰。若源和目标子载波不同，最多涉及两个子载波族上的 `2K` 个接收块。实现按 `(uav, subcarrier)` 缓存接收功率、干扰、解码次序和速率，并只更新受影响块。随后收集所有速率或服务归属发生变化的任务，对包含这些任务的每一架 MEC 服务器重新执行 DD-MCAA；服务器内其他任务即使无线速率未变，也可能因 CPU 需求排序和准入集合变化成为第三方受影响任务。

增量评价必须在至少 10,000 个随机合法动作上与完整重算逐字段一致；任一完成状态、SINR、SIC、CPU、目标分量或接受判定不一致，正式实验禁止启动。

### 5.7 理论命题

论文至少给出以下命题和完整证明：

**命题 1：调度可行性保持。** 三类动作经过必要过滤和统一评价后，不破坏唯一任务、每块 NOMA 容量和服务归属一致性。

**命题 2：严格单调性。** IEA-CAP 接受的每个动作均使有限字典序目标 `Phi` 严格改善。

**命题 3：有限终止。** 在有限调度空间与严格改善准则下，任一起点搜索不可能循环并在有限步内终止。

**命题 4：邻域局部最优。** 当搜索穷尽 Replace、Position 和 CrossUAV 联合邻域后，终止调度在该邻域中不存在严格改善动作。

**命题 5：增量评价等价。** 若缓存依赖集合包含源/目标块、全部同频接收端，以及所有包含受影响任务的 MEC 服务器，则增量结果与全网完整重算一致。

不得把命题 4 外推为一般规模全局最优，也不得声称全网接受的终端解必然优于另一接受规则的终端解；二者搜索路径不同。

### 5.8 复杂度边界

令无线位置数 `P=2KS`，当前需卸载任务数为 `A<=N`，多起点数量为 `M`，每个起点实际接受动作数为 `R`。Replace 候选数不超过 `O(PN)`，Position 与 CrossUAV 候选总数不超过 `O(P^2)`。一次增量候选评价更新至多 `2K` 个同频资源块，以及全部受影响 UAV 上的资源响应；采用排序实现时，其保守复杂度为 `O(K + N log N)`。

因此实际搜索的保守上界写为：

`O(M R (PN + P^2) (K + N log N))`

论文同时报告候选数、完整评价次数、缓存命中率和实测运行时间。`R` 是实例相关量，不把有限状态空间的指数级最坏终止步数隐藏为多项式保证。

## 6. 创新点二：DD-MCAA 的最终设计

### 6.1 创新定义

DD-MCAA 是**截止时间驱动的最小成本卸载与 MEC 算力准入分配方法**。它将硬截止约束转化为每个任务的最小卸载比例和最小 MEC CPU 消耗，再利用单位价值任务的结构求解最大完成基数准入。

### 6.2 最小卸载比例

本地分支满足截止时间需要：

`(1 - alpha_i) L_i c_i / f_i^loc <= tau_i`

因此：

`alpha_i^min = clip(1 - tau_i f_i^loc / (L_i c_i), 0, 1)`

当 `alpha_i^min = 0` 时，任务可以纯本地按时完成，不占用无线和 MEC CPU；当当前无线调度不可行、剩余时限非正或数值输入非有限时，任务在当前调度下不可完成。

### 6.3 最小 MEC CPU

记上传与结果返回的单位卸载数据通信时间系数为：

`b_i = (1 + rho_i) L_i / R_i`

边缘分支满足截止时间需要：

`alpha_i b_i + alpha_i L_i c_i / f_i^mec <= tau_i`

因此在 `tau_i - alpha_i b_i > 0` 时：

`f_i^min(alpha_i) = alpha_i L_i c_i / (tau_i - alpha_i b_i)`

该函数在可行区间内关于 `alpha_i` 严格递增，所以最小 CPU 出现在 `alpha_i = alpha_i^min`。若分母非正、最低 CPU 超过单 UAV 预算或 SIC/速率不可行，则任务不进入候选准入集合。

### 6.4 最大基数准入

对每架 UAV 独立构造可行任务集合，按 `(f_i^min, task_id)` 稳定升序排列，并在 CPU 预算内取最长可行前缀。未进入前缀的任务不分配 MEC CPU；进入前缀的任务首先分配其最小需求。

### 6.5 理论命题

**定理 1：最小卸载比例正确性。** `alpha_i^min` 是使本地分支满足截止时间的最小可行卸载比例。

**定理 2：最小 CPU 正确性。** 在固定速率和 `alpha_i = alpha_i^min` 下，`f_i^min` 是使边缘分支满足截止时间的最小 MEC CPU。

**定理 3：最大完成基数与最小成本最优性。** 在固定无线调度、单位任务价值、任务 CPU 消耗相互独立且每个任务只占用一个 UAV CPU 预算的条件下，按 `f_i^min` 非降序选择最长可行前缀可获得最大按时完成任务数；在所有最大基数集合中，该前缀同时具有最小的 `f_i^min` 总需求。

证明采用交换论证：任何包含较大 CPU 需求而排除更小需求的同基数方案，都可用更小需求任务替换而不增加总消耗；最小 `q` 个需求之和若超过预算，则不存在包含 `q` 个任务的可行方案。

**定理 4：复杂度。** 解析需求计算为 `O(n_u)`，排序为 `O(n_u log n_u)`，扫描为 `O(n_u)`；全系统复杂度为 `O(N log N)`。

定理 3 不适用于异质任务权重、多服务器联合拆分、共享缓存或任务间依赖，也不声称无线调度和卸载比例的联合全局最优。论文必须明确这些边界。

## 7. 联合方法 EAD-JSRA

EAD-JSRA 不是第三个独立创新点，而是两项方法的闭环组合：

1. IEA-CAP 生成或修改无线调度；
2. 当前调度确定真实接收 UAV、同频干扰、NOMA/SIC 和传输速率；
3. DD-MCAA 反推最小卸载比例、最小 CPU 和准入结果；
4. 统一时延函数输出完成数和最低 CPU 总需求；
5. IEA-CAP 使用完成数、最低 CPU 总需求和跨 UAV 干扰构成全网目标，决定是否接受候选；
6. 循环至联合邻域局部最优。

因此，全网评价由 IEA-CAP 的评价器负责，DD-MCAA 是评价器内部的资源响应模块，而不是“全网评价算法”本身。

## 8. 基线体系

### 8.1 同模型强基线

- `Local-only`：所有可本地完成任务在本地执行；
- `Fair-OFDMA`：跨用户正交接入，用于区分 NOMA 容量收益与调度收益；
- `Greedy`：按局部信道或速率贪心关联；
- `IA-Greedy`：候选通过统一全网物理评价的干扰感知贪心；
- `per-UAV ILP`：每架 UAV 局部优化，不执行跨 UAV 外部性协调；
- `Exchange-Stable`：双边交换稳定机制基线；
- `Intra-Global`：有全网接受但无 CrossUAV 邻域；
- `Cross-Bilateral`：有 CrossUAV 邻域但只做双边接受；
- `IEA-CAP-SingleFirst`：单起点首次改进消融；
- `IEA-CAP`：多起点最佳改进完整方法。

结构消融中的 `IEA-CAP`、`Intra-Global` 和 `Cross-Bilateral` 必须使用完全相同的三个初始解、最佳改进策略、候选穷尽规则、数值量化、确定性 tie-break 和停止条件。H1 只对 `Intra-Global` 关闭跨 UAV 动作；H2 只将 `Cross-Bilateral` 的候选排序和接受效用替换为不含第三方信息的双边效用，不得继续使用全网目标排序候选。由此，H1 的差异仅归因于 CrossUAV 邻域，H2 的差异仅归因于全网外部性评价。

### 8.2 资源分配强基线

- `EDF-MinCPU`：先计算最小 CPU，再按最早截止时间准入；
- `MinSlack-MinCPU`：按最小初始裕量准入；
- `Exact Admission Oracle`：对固定无线调度枚举或动态规划求最大完成基数；
- `AlphaMin/Equal`：使用最小卸载比例但平均分 CPU，用于隔离准入机制；
- `Fixed 0.5/Equal` 与 `Crossing/Equal`：只作朴素受控消融，不称为 SOTA。

### 8.3 文献基线准入规则

近年多 UAV NOMA-MEC 工作常同时优化轨迹、功率、带宽、长期能耗或跨 UAV 任务迁移，与本文固定悬停、固定功率、硬截止完成基数问题不等价。正式稿采用以下规则：

1. 有作者代码且决策变量可对齐：原始实现进入正式比较；
2. 必须冻结轨迹/功率等变量：命名为 `*-static-adapted`，披露删除的动作和训练预算；
3. 无代码或目标不可比：只进入文献对照表，不自行补全为“复现 SOTA”；
4. 正式实验前至少满足下列二者之一：一项可审计的近年适配基线，或完整的小规模 Exact Schedule Oracle 加三项同口径强基线；
5. 所有算法共享任务、位置、真实/估计大尺度信道增益、功率、CPU、种子和最终评价器。

优先申请并评估 Lin et al. 2025 的 `POS_MADDPG_NOMA` 代码；取得代码后只能以预注册的 `POS-MADDPG-NOMA-static-adapted` 名称补充。若无法取得足够信息，不阻塞同口径主实验，但不得出现“全面超越 SOTA”的表述。

| ID | 研究问题 | 方法 | 场景 |

外部性主实验采用三个因素的 `2^3` 端点设计：热点重叠度低/高、交叉接收耦合 `0/1.0`、无线负载 `0.8/1.2`，另加中心点 `medium/0.5/1.0`，共 9 个冻结条件。热点重叠指标定义为“活跃用户中两个最强 UAV 大尺度信道增益相差不超过 3 dB 的比例”；low、medium、high 分别校准到 `<=15%`、`30%–45%`、`>=60%`，校准只允许改变冻结的热点标准差，不能查看算法结果。负载 `1.5` 和其他中间水平只作单因素边界扫描，不进入 H2。不得看结果后移动场景边界。

Exact Schedule Oracle 使用 K2、N5、S1、同步初相位和 `2 GHz/UAV` CPU 预算，使无线位置与 MEC 资源都存在竞争。非平凡性门禁为：在至少 30% 的可评价时隙中，`Exact完成数 < 到达且需卸载任务数`。未达到该条件时，Exact 结果只算正确性测试，不得用于“接近全局最优”的性能证据。

Exact 比较必须逐时隙依次报告：完成数 gap；完成数相等时的最低 CPU 总需求 gap；前两层相等时的跨 UAV 干扰 gap。“达到全局最优的时隙比例”仅指算法输出与 Oracle 的完整量化字典序目标完全相等；仅第一层相等时只能称为“达到最大完成基数的时隙比例”。

### 11.4 功效与精度

正式种子打开前，只使用 pilot 种子估计各主假设的种子级配对差分布。最小有意义效应固定为：H1/H2 `0.5 pp`，H3/H4 `2 pp`。样本量通过 pilot 配对重采样模拟 H1–H4 的完整 Holm 决策过程，使每个主假设在校正后的目标功效不低于 80%；若不执行该模拟，则保守按单假设双侧 `alpha=0.0125` 和 80% 功效计算。所需样本量向上取整到 `{50,100,200}`，写入冻结配置后一次性完成。正式结果不得触发扩样或提前停止。若估计所需样本量超过 200，则相应性能主张标记为证据不足，不能通过事后降低效应阈值解决。

### 11.5 冻结主假设

- **H1（CrossUAV 主效应）**：主场景 K3N45 周期任务中，`IEA-CAP > Intra-Global`，最小有意义效应 `0.5 pp`；
- **H2（全网接受主效应）**：外部性压力场景 `offered_load=1.2、overlap=high、coupling=1.0` 中，`IEA-CAP > Cross-Bilateral`，最小有意义效应 `0.5 pp`；
- **H3（DD 准入主效应）**：K3N45、`4 GHz/UAV`、任务 `0.8–3.0 Mbit`、`800–1500 cycles/bit`、deadline `0.6–1.0 s` 的固定无线调度中，`DD-MCAA > EDF-MinCPU`，最小有意义效应 `2 pp`；
- **H4（联合方法）**：主场景中，`IEA-CAP+DD-MCAA > Exchange-Stable+EDF-MinCPU`，最小有意义效应 `2 pp`。

四个主假设在正式配置中逐项登记，并共同执行 Holm 校正。DD 对 MinSlack、IEA 对 IA-Greedy/Exchange-Stable、其他压力点和所有鲁棒性结果均为辅助分析，不得替代失败的 H1–H4。

### 11.6 推断方法

- 主结果：种子聚类的 10,000 次配对 bootstrap 95% CI；
- 辅助检验：Wilcoxon signed-rank；
- 多重比较：H1–H4 共同 Holm 校正；辅助实验在各自预注册实验族内另做 Holm 校正；
- 效应量：matched rank-biserial correlation；
- Exact Oracle：逐实例相等率与最优 gap，不做伪显著性检验；
- 所有图同时显示种子点、均值/中位数和置信区间，不能只画柱状图。

## 12. 指标体系

### 12.1 主指标

- On-time completion rate：唯一到达任务中按时完成任务的比例；
- Seed-level completed tasks：每个 episode 的完成任务数。

### 12.2 机制指标

- 已准入任务的最低 CPU 总需求、单位完成任务 CPU 成本；
- bilateral 接受而 global 拒绝的事件率；
- 每个动作受影响第三方任务数；
- 第三方完成状态、最低 CPU、速率和 SINR 变化；
- Replace/Position/CrossUAV 候选数、接受数和边际收益；
- 重叠区域用户完成率和 Jain 公平性；
- SINR、INR、SIC outage 与无线调度率；
- 最小卸载比例、最小 CPU、CPU 预算绑定率和漏任务原因。

### 12.3 效率与正确性指标

- P50/P95 在线运行时间；
- 候选评价次数与增量缓存命中率；
- Exact Schedule Oracle 完成数 gap；
- DD 与 Exact Admission Oracle 逐实例一致率；
- 唯一任务、块容量、SIC、CPU、非收敛、校验和违规数。

## 13. 论文证据硬门禁

### 13.1 不可妥协门禁

以下任一失败都禁止生成 `canonical/v2`，相关结果不得写成论文结论：

1. 全量自动化测试未通过；
2. 任何正式调度出现任务重复、NOMA 容量、SIC 或 CPU 硬约束违规；
3. 增量评价与完整评价存在任何语义差异；
4. DD-MCAA 与 Exact Admission Oracle 在单位价值固定调度实例上完成基数或最大基数下的最低 CPU 总需求不一致；
5. 任务、信道增益或调度轨迹在方法之间不一致；
6. 分析图表不是从 canonical bundle 自动生成；
7. 参数来源、代码提交、配置、随机种子或 SHA-256 不完整；
8. 论文出现未运行数字、手工改数或虚构 SOTA 基线。

### 13.2 创新点一绿色门禁

IEA-CAP 同时满足：

- 100% 接受动作严格改善 `Phi`；
- 100% 正式终止解通过联合邻域局部最优复核；
- 预注册压力场景中存在可复核的第三方外部性事件；
- H1 中 `IEA-CAP - Intra-Global >= 0.5 pp`，95% CI 下界大于 0，Holm 校正后 `p<0.05`；
- H2 中 `IEA-CAP - Cross-Bilateral >= 0.5 pp`，95% CI 下界大于 0，Holm 校正后 `p<0.05`；
- Exact 小实例完整量化字典序目标达到全局最优的时隙比例至少 95%；完成数平均 gap 不超过 0.05、最大 gap 不超过 1，并分别报告完成数相等条件下的最低 CPU gap 与前两层相等条件下的干扰 gap；
- 增量评价相对完整重算至少加速 3 倍且结果完全一致。

若只能证明机制但不能达到结构消融性能门禁，论文只能保留限定机制结论，不得形成“性能领先”的主张。

### 13.3 创新点二绿色门禁

DD-MCAA 同时满足：

- 与 Exact Admission Oracle 的完成基数和最大基数下最低 CPU 总需求 100% 一致；
- H3 中 `DD-MCAA - EDF-MinCPU >= 2 pp`，95% CI 下界大于 0，Holm 校正后 `p<0.05`；
- 相对 `MinSlack-MinCPU` 的非劣界下限高于 `-0.5 pp`；
- 所有不可行原因可分类为无线/SIC、时限分母、单任务超预算或总预算准入；
- 在线复杂度曲线与 `O(N log N)` 一致，无异常超线性实现瓶颈。

### 13.4 联合方法绿色门禁

- H4 中 `EAD-JSRA - (Exchange-Stable+EDF-MinCPU) >= 2 pp`，95% CI 下界大于 0，Holm 校正后 `p<0.05`；
- 相对两个单组件组合均不出现超过 0.5 pp 的实质退化；
- 两个主效应方向与各自单独实验一致；
- 若交互项为负，必须定量解释并报告，不能隐藏。

### 13.5 工程门禁

- 冻结正式配置前，K3N45 与 K5N75 均完成 `5 seeds × 20 slots` 复杂度审计，给出单槽 P50/P95、候选数、峰值内存、日志量和正式实验总 CPU 时间预测；
- K3N45 主场景 P95 在线调度时间小于 1 s；
- K5N75 P95 小于 10 s；
- 正式任务支持按种子分片、断点续跑和确定性合并；
- 任一分片重跑不改变其他分片校验和；
- 单实验族原始日志大小有上限，summary 日志不得在内存中积累全部候选事件。

## 19. 失败回退路径

### 19.1 IEA-CAP 效果不足

1. 先检查实现、负载天花板、增量等价和多起点是否正确；
2. 在不查看正式种子结果的开发集上比较首次/最佳改进、单/多起点和安全剪枝；
3. 若机制成立但结构消融效果仍小，将结论限定为外部性识别和约束可行性，不扩展为普遍性能优势；
4. 未达到绿色门禁时，不得使用“性能领先”主张；
5. 不通过删除不利场景、改种子或只报告显著子组来补救。

### 19.2 DD-MCAA 不匹配 Oracle

这是算法或实现错误，不是实验负面结果。立即停止，复查单位价值、纯本地任务、浮点边界、分母、tie-break 和最终时延复核，直到逐实例 100% 一致。

### 19.3 联合方法交互为负

保留 2×2 结果并定位：无线调度是否提高速率但集中 CPU 压力，或 DD 准入是否改变 IEA 目标地形。若联合方法低于两个单组件超过 0.5 pp，不能只保留联合方法相对弱基线的结果，也不得形成联合性能优势结论。

### 19.4 文献代码不可得

保留完整可比性审计，使用三项同口径强基线和 Exact Schedule Oracle，明确不做虚假复现，也不编造一个同名文献算法。

### 19.5 运行时间超标

只允许通过精确增量缓存、安全剪枝、分片并行和数据结构优化降时，不允许减少候选邻域后仍沿用相同局部最优主张。

## 20. 完成定义

本方案完成不是“所有实验跑完”，而是同时满足：

1. 两项创新各有明确问题、算法、理论命题、强基线、精确参照和适用边界；
2. 周期任务、现实参数、真实移动补充和多信道模型形成外部效度链；
3. Main、Externality、Resource、Exact、Joint、Scaling、Robustness 和 Trace-driven 八个证据族闭环；
4. 统计以种子为独立单位，功效、置信区间、多重比较和效应量齐全；
5. `canonical/v2` 可从源码、配置和种子复现，所有硬约束零违规；
6. 论文所有主张均能在 `claim_matrix.csv` 中映射到公式、定理、实验和产物路径。

达到以上条件表示论文的方案、实现、实验、数据和结论已经形成闭环。
