## 步骤1.1：DPA算法竞争比证明 🔴 最高优先级

### 目标
证明DPA（分布式相位调整）贪心算法的理论性能保证。

### 输入文档
- 阅读 [03_算法设计_相位对齐调度.md](./03_算法设计_相位对齐调度.md) §4 DPA算法

### 执行步骤

**Step 1**: 理解DPA算法机制
```
DPA策略：当新车辆加入时，选择当前最大相位间隔的中点作为其相位

示例：
- 初始：车辆A的相位=0.0
- 车辆B加入：最大间隔=[0, T_check]，选中点 → φ_B = T_check/2
- 车辆C加入：最大间隔=[0, T_check/2]或[T_check/2, T_check]，选其中点
```

**Step 2**: 定义优化目标
```
目标：最小化最大相位间隔 (Min-Max Gap)
- 设n辆车的相位为 {φ₁, φ₂, ..., φₙ}（已排序）
- 最大间隔 G_max = max{ φ_{i+1} - φᵢ, T_check - φₙ + φ₁ }
- 最优解 OPT：G*_max = T_check / n（均匀分布）
```

**Step 3**: 分析DPA的最坏情况
```
引理1：DPA算法执行后，任意两个相邻间隔的比值不超过2

证明思路：
- 每次插入选择最大间隔中点
- 设最大间隔为G，插入后分为两个G/2的间隔
- 其他间隔不变
- 因此新的最大间隔 ≤ max(G/2, 第二大间隔)
- 递归分析...
```

**Step 4**: 推导竞争比
```
定理：DPA算法是2-competitive的

证明：
1. n辆车的最优最大间隔：G*_max = T_check / n
2. DPA的最大间隔：G_DPA ≤ 2 · T_check / n
3. 竞争比 = G_DPA / G*_max ≤ 2

最坏情况构造：
- 依次到达的车辆位置使DPA始终选择次优位置
- 给出达到竞争比2的具体实例
```

**Step 5**: 讨论紧致性
```
问题：竞争比2是否紧致（tight）？
- 如果是，给出达到下界的实例
- 如果不是，讨论可能的更紧上界
```

## 步骤1.2：预测误差理论模型 🔴 高优先级

### 目标
推导预测误差ε对AoI增量的数学关系式。

### 输入文档
- 阅读 [04_算法设计_任务负载预测.md](./04_算法设计_任务负载预测.md)
- 阅读 [02_问题形式化与理论分析.md](./02_问题形式化与理论分析.md) §3 AoI定义

### 执行步骤

**Step 1**: 定义预测误差模型
```
设：
- 真实任务触发时刻：t_real
- 预测触发时刻：t_pred
- 预测误差参数：ε ∈ [0, 1]
  - ε = 0：完美预测
  - ε = 1：随机猜测

误差分布建模：
δ = t_pred - t_real ~ N(0, σ²)
其中 σ = ε · T_check（标准差与误差参数成正比）
```

**Step 2**: 分析完美预测下的AoI
```
假设完美预测（ε = 0）：
- 任务在t_real时刻触发
- 系统已预先分配资源
- 任务立即开始处理
- 完成时刻：t_complete = t_real + T_process
- AoI峰值：A_peak = T_process
- 平均AoI：A_avg_perfect = T_check/2 + T_process/2（近似）
```

**Step 3**: 分析有误差时的AoI
```
有预测误差（ε > 0）时：

情况1：预测偏早（δ < 0，即t_pred < t_real）
- 资源预留了但任务未到
- 等待时间增加：|δ|
- AoI影响：资源可能被浪费

情况2：预测偏晚（δ > 0，即t_pred > t_real）
- 任务到达但资源未准备好
- 额外排队时间：δ
- AoI增量：ΔA ≈ δ

综合期望：
E[ΔA] = E[max(0, δ)] = ∫₀^∞ δ · f(δ) dδ
      = σ / √(2π)  （半正态分布的均值）
      = ε · T_check / √(2π)
```

**Step 4**: 推导AoI增量公式
```
AoI增量近似公式：

ΔA(ε) = α · ε · T_check + β · ε² · T_check

其中：
- 一阶项：直接延迟影响
- 二阶项：资源浪费导致的间接影响（如排队效应）
- α, β 为常数，可通过仿真标定

简化形式（当ε较小时）：
ΔA(ε) ≈ c · ε · T_check

其中 c ≈ 0.3-0.5（取决于系统负载）
```

**Step 5**: 确定可容忍误差阈值
```
分析：
- 若要求 ΔA/A_avg < 5%（可接受）
- 则 ε < 5% / c ≈ 0.1-0.15

结论：
- ε < 0.1：AoI增加 < 5%，可容忍
- 0.1 < ε < 0.3：AoI增加 5-15%，需权衡
- ε > 0.5：预测优势基本消失
```

## 步骤1.3：公平性分析框架 🟡 中优先级

### 目标
设计Jain公平性指数的应用框架，论证"按需分配"的合理性。

### 输入文档
- 阅读 [12_研究阶段划分与优先级.md](./12_研究阶段划分与优先级.md) §任务2.3

### 执行步骤

**Step 1**: 定义Jain公平性指数
```
对于N辆车的AoI分布 {A₁, A₂, ..., Aₙ}：

JFI = (Σᵢ Aᵢ)² / (N · Σᵢ Aᵢ²)

性质：
- JFI ∈ [1/N, 1]
- JFI = 1：完全公平（所有车辆AoI相同）
- JFI → 1/N：完全不公平
```

**Step 2**: 分析资源分配的异质性来源
```
异质性来源：
1. 速度差异：高速车触发频率高（最大10Hz vs 低速2.5Hz）
2. 任务大小：感知范围大的车辆CPM数据量大
3. 位置差异：距RSU远近影响传输速率

结果：高速车辆自然占用更多资源
```

**Step 3**: 对比两种分配策略
```
策略A：按需分配（本文采用）
- 描述：触发多的车获得更多资源
- AoI：最优
- 公平性：JFI可能较低
- 适用：安全敏感场景

策略B：均匀分配
- 描述：每辆车资源配额相同
- AoI：高速车恶化
- 公平性：JFI = 1
- 适用：公平性敏感场景
```

**Step 4**: 论证按需分配的合理性
```
核心论点：
"高速车辆的信息更新需求与其安全需求成正比。
按需分配不是算法缺陷，而是系统需求驱动的设计选择。"

支撑论据：
1. 安全需求：120km/h的车在100ms内移动3.3m，需要更频繁更新
2. ETSI标准设计意图：事件触发机制本身就是按需设计
3. 实际部署考量：可通过权重调整在AoI和公平性间权衡
```
